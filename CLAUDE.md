# Claw

Низкоуровневый компилируемый язык, целиком написанный Claude. Вопрос, на который он отвечает:
какой системный язык нужен, если код пишет ИИ, а отвечает за него человек.

Полный план: `docs/PLAN.md`. Решения и их причины: `docs/DECISIONS.md`. Что реально работает: `docs/STATUS.md`.

## Принципы (проверяй каждую фичу по ним)

1. Язык помещается в промпт: ядро `docs/CARD.md` не больше 2500 токенов (было 2000 до 0.13). Фича платит за своё место.
2. Лапа и Коготь: `fn` безопасен и без ручной памяти, `claw fn` как чистый C. Рантайма и GC нет.
3. Контракты `need/sure`: доказать или проверить, молчать нельзя.
4. Тесты пишет компилятор: фаззинг функций без эффектов.
5. `claw why`: причина падения, а не адрес.
6. Подпись говорит правду: эффекты `+mem +io`.
7. Считаем токены всего цикла: написать, прочитать, исправить.
8. От исходника до бинарника только наш код: без LLVM, `as`, `ld`.

Правило синтаксиса: странной пунктуации нет, свежесть в смыслах. 1-2 способа сделать одну вещь.
Ключевые слова: обычные короткие английские слова в один токен.

## Команды

```bash
cargo build --release --manifest-path compiler/Cargo.toml   # сборка, без предупреждений
python3 tools/runtests.py                                   # все тесты всех итераций; tests/own сверяют alloc и free
python3 tools/check_encoder.py                              # сверка ARM64-энкодера с llvm-mc
python3 benchmarks/run.py                                   # замеры против clang
python3 tools/tokens.py                                     # оценка токенов: Claw против C и Rust, пишет benchmarks/TOKENS.md
python3 tools/exam.py <папка> [--tasks=tasks2.json]         # оценка ответов экзамена по карточке
python3 tools/install.py                                    # установка версии в ~/.claw
```

Компилятор на самом Claw: `selfhost/` (правила переноса в `selfhost/PORTING.md`). Мерка: байты как у `claw build --no-opt`; самосборку до неподвижной точки проверяет `tools/runtests.py`.


## Устройство

`compiler/src`: `lexer → parser → ast → sema → effects → lower → cir → codegen (arm64) → macho + sha256`, ошибки в `diag`.
Режимы: `claw build` без контрактов с вызовами; `claw run` и `claw test` со всеми проверками и `std/check_rt.claw`.
Интерпретатор `interp` исполняет CIR (режим lowering `Opts.interp`): на нём стоят `ctfe` (вычисление `const`), `fuzz` (автотесты) и `why` (причина падения). Он обязан совпадать с машинным кодом: это проверяют `tools/runtests.py` и `tools/fuzz_opt.py`.
Stage 0 на Rust без внешних crates. Цель только macOS ARM64 до итерации 10.

Формат Mach-O и подписи сверяй с реальным выводом `clang` (`otool -l`, `codesign -dvvv`, `dyld_info`), а не по памяти.

## Чек-лист конца итерации

1. `cargo build --release` без предупреждений.
2. `tools/runtests.py`: все тесты, включая тесты прошлых итераций. Старые тесты не удалять.
3. `tools/install.py`, затем `claw-0.N --version` из нового shell. **Старые версии в `~/.claw` никогда не удалять.**
4. Обновить `docs/STATUS.md` и `benchmarks/RESULTS.md`.
5. git commit и тег `v0.N`.
6. Отчёт пользователю простым языком: что из синтаксиса работает, что нет.

## Как работать

- Пользователь знает C, C++ и Python: объяснять через них и по-простому, на русском.
- Не больше одного субагента за раз, если пользователь не просил иного.
- Не обещать скорость без замеров: прогноз называть прогнозом.
- Значимые решения записывать в `docs/DECISIONS.md`.
- Каждое новое правило компилятора: стабильный код ошибки `E####`, тест в `tests/err`, по возможности готовый патч.
- Зарезервированные, но ещё не реализованные конструкции дают `E0900`, а не странную ошибку разбора.
