# Переносим компилятор на Claw

Цель итерации 9: `selfhost/main.claw` компилирует сам себя. Rust-компилятор (`compiler/src`) остаётся эталоном и единственным местом, где живут оптимизатор, `why`, фаззер, `fmt`, `fix`.

## Что переносим, а что нет

Переносим дословно, модуль за модулем: `lexer` (готов), `diag` (готов), `ast`, `parser`, `modules`, `types`, `sema`, `effects`, `cir`, `lower`, наивная ветка `regalloc`/`codegen`, `arm64`, `macho`, `sha256` (готов).

Не переносим: `opt`, `ssa`, `ranges`, распределение регистров, `interp`, `fuzz`, `why`, `ctfe`, `fmt`, патчи `fix`. Вычисляемые `const` (`const x T = f()`) компилятор на Claw отвергает с `E0174`.

## Мерка: байт в байт

`claw build --no-opt f.claw` в Rust и `selfhost f.claw` обязаны дать **одинаковые байты**. Промежуточные мерки: `claw __tokens` (лексер), `claw __ast` (парсер), `claw --emit-cir --no-opt` (lowering), коды ошибок в заголовках `tests/err` (sema). Поведение меняем только там, где Rust нельзя повторить, и пишем об этом сюда.

## Как писать

- Имена функций, полей и вариантов те же, что в Rust, если язык позволяет.
- Вариант живёт в пространстве имён модуля: два варианта с одним именем в одном файле нельзя, добавляй префикс.
- Рекурсии типов нет, поэтому **дерево живёт в арене**: `ast.Ast { exprs []Expr, stmts []Stmt, blocks []Block, tys []TypeExpr }`, ссылка это индекс `int`, «нет значения» это `-1`, список это `[]int`. Sema пишет `ty`, `coerce`, `res` прямо в элемент арены.
- Глобальных изменяемых переменных нет: состояние передаётся параметром `&`.
- Типы из другого модуля пишутся с именем модуля: `diag.Span`, `ast.Expr`. Шаблоны и функции из `core` видны везде.
- Эффекты `pub`-функций не пиши руками: `claw fix файл` их добавит.
- Целые: `int` это i64. `i128` нет. Литералы: `u64` и флаг `big` у токена. Для `eval_const` хватит `int`, если значение не влезает, повтори поведение через флаги.

## Ловушки языка

- `{` в строке всегда выражение: литеральная скобка это `{{`.
- `if` это инструкция, не выражение. Нет `?:`, нет голых блоков `{ }`.
- `x := a[i]`, если тип владеет памятью, это вид: `a` нельзя менять до конца блока. Для `mut` нужен `copy`. Параметр `x T` только читает; переместить его можно, если он объявлен `own`.
- Массив `[N]T` копируется при присваивании. Чтобы не копировать большое, передавай параметром.
- Нет методов, замыканий, перегрузки. `match` по числам и строкам есть только для чисел; строки сравнивай `==`.
- Строк в `match` нет. Длинные цепочки `if name == "..."` это нормально.
- Подробная справка: `docs/CARD.md`, подписи библиотеки: `claw sig std`.
- `selfhost/rt.claw`: чтение файла, запись, аргументы, `text(own []u8) str` без копии.
- `match a.exprs[i].kind` тоже вид: пока он жив, `&a` передавать нельзя. Нужен обход с записью в арену: `k := copy(a.exprs[i].kind)`, потом `match k`.
- Значение `?str` из параметра или поля можно читать через `else` только после `copy`, иначе это перемещение.
- Внутри `{...}` в строке нельзя писать `"`: строка кончится раньше. Вынеси в переменную.
- Длинный `type X = A | B` переносится только после `|`, а не перед ним. Многострочная ветка `match` идёт в `{ }`.
- Вариант без полей из другого модуля пишется `ast.Break`, как значение; `E0152` на нём был ошибкой компилятора (исправлена).

## Сознательные отличия от Rust

- `modules.find_std` ищет `std` рядом с компилятором, а затем в каждой папке выше: так бинарник из `selfhost/` находит `std` репозитория. В Rust проверяются только папка компилятора и третья над ней.
- В сообщении об ошибке с литералом больше 64 бит (`found number ...`) стоит текст из исходника без `_`, а не значение i128; для шестнадцатеричных и для чисел больше i128::MAX текст другой. Внутри `{...}` в строке, где исходника нет, пишется `big`.

## Сборка

`compiler/target/release/claw` собирает `selfhost/*.claw`. `use x` ищет `x.claw` рядом с файлом.

## Sema и эффекты (`types`, `sema`, `effects`, `wide`, `dump_sema`)

Мерка: `claw __sema [--check] [--tests] файл` (Rust) и `dump_sema` дают **одинаковый текст** на всём корпусе (`tests/**`, `std`, `selfhost`, `benchmarks`) во всех четырёх режимах. Сравнивать так: `dump_sema` кладётся рядом со `std`, например симлинком `std` в папке с бинарником; пути `std` в выводе тогда отличаются только префиксом, его надо заменить перед сравнением.

Как устроено:
- `sema` читает дерево как **параметр только для чтения** (`l modules.Loaded`) и не пишет в арену, пока работает: иначе `match l.a.exprs[e].kind` заблокировал бы `&`-вызовы, и каждый разбор требовал бы `copy`. Ответы лежат в `Global.ty/coerce/res` (по одному элементу на `Expr`), их `check` записывает в арену в самом конце. Экземпляр шаблона это `clone_func`: новые id, таблицы растут через `new_tables`.
- `Global` содержит и состояние всего модуля, и состояние проверяемого тела (`Ctx` в Rust): рекурсии в `check_body` нет, состояние пересоздаётся на входе. `l`, `g` протягиваются везде.
- `FnSig` и `Func` не копируются при поиске: `sigs` хранит индекс в `sig_list`.
- `HashMap` в Rust итерируется случайно. Там, где это влияло на результат (`instance_of`), Rust теперь сортирует по id типа, а порт хранит список в порядке создания (`insts`): это тот же порядок. `user_drop`, `known`, `sigs` в дампе сортируются.
- `Types` интернирует сам (открытая адресация по `kind_hash`, сравнение `kind_eq`), без `Map` и без строковых ключей.
- `types.name` пишет в один буфер: тип `[2][2]...` бывает глубиной в тысячи, и `"[{n}]{inner}"` на каждом уровне было бы квадратично (`tests/err/generic_infinite_fn` падал по времени).
- Числа в `const`: `wide.claw` повторяет i128 (`checked_*`, сдвиги, `as f64`). Литерал больше `u64` помечен `big`: цифры потеряны ещё в лексере.

Ловушки, которые попались здесь:
- `own` это ключевое слово: поле называется `owned`.
- Локальная переменная не может называться как функция этого модуля (`E0102`), даже если вызывается через другой модуль. Отсюда `er` вместо `err`, `vname` вместо `var`: функции `err` и `var` есть в `sema`.
- `swap(&d[i], &d[j])` по одному массиву запрещён (`E0158`): такой `swap` делается через `remove`/`insert`.
- Читать поле `?BinOp` из вида можно: `o := op else ast.Add`; `?str` только через `copy` (`opt_text`).
- `if` не даёт значения, `match` не выражение: везде `mut x := ...`, потом присваивание в ветках.
- Внутри `{...}` строки нельзя вложить `"`: `{join(xs, ", ")}` выносится в локальную переменную.
- У рекурсивного разбора нет большого стека: `rt.ensure_stack()` поднимает лимит стека (`setrlimit` + повторный `exec`), Rust для этого запускает поток на 256 МБ. Левая вложенность `1 + 1 + ...` в 6000 звеньев (`tests/run/large_frame`) требует десятки мегабайт.

Сознательные отличия от Rust (только про литералы больше `u64`, которых нет в тестах):
- `index ... is outside`: для такого индекса вместо значения пишется `big`.
- Такой литерал в `const x f64`: Rust считает значение, порт отвечает `E0115`, так как цифр нет.
- `const x = 99999999999999999999 / 1000`: Rust считает, порт видит `big` и отвечает `E0115` на типизированную проверку.
- `E0151` из `defer` с двумя и более переменными: Rust берёт первую в случайном порядке `HashMap`, порт первую по порядку появления.

Вычисляемые `const` здесь не считаются: `resolve_computed` и проверки на месте, `E0174` даёт следующая стадия.

## CIR и lowering (`cir`, `lower`, `dump_cir`)

Мерка: `claw __cir [--check] [--tests] [--fast] [--regs] файл` (Rust, без `opt`) и `dump_cir` с теми же флагами дают **одинаковые байты**. Без флагов это `claw build --no-opt`, `--fast` это `claw build --fast --no-opt`, `--check` это `claw run`, `--check --tests` это `claw test --blocks`, `--regs` сверяет `each`/`def_of`/`is_call`. Бинарник класть в `compiler/target/release/`, иначе не найдётся `std`. Исключения только три: `tests/info/sig_all`, `tests/run/const_computed`, `tests/run/const_computed_uses` (вычисляемые `const`, порт отвечает `E0174`). Объявленный, но не использованный вычисляемый `const` лишь даёт функцию `const x`, как в Rust.

Как устроено:
- `Lower` это `FnLower` и `Env` Rust вместе; `new_lower` сбрасывает всё, что живёт одну функцию, блоки и объекты в конце уходят через `swap` в `into_func`.
- `l` и `c` передаются везде параметрами только для чтения, поэтому `match l.a.exprs[e].kind` не мешает вызовам с `&me`. Сам `me` так читать нельзя: сначала взять `int`, а не вид.
- Замыканий нет: `counted_loop` стал `counted_open`/`counted_close`, `on_tag` стал `tag_open`/`tag_close`, `for_each` стал `for_each_drop` (тело всегда было drop).
- `Option<VReg>` это `int` со значением -1; `Clean`, `Place`, `Piece` простые варианты. Функция называется по `FuncRef{unit, index}`: `ast.Func` нельзя вернуть видом и нельзя положить в структуру, поэтому пара и две ветки вызова.
- `olds` и `under_old` ключуются номером выражения: у экземпляра шаблона (`clone_func`) номера свои, как и адреса в Rust.
- Не перенесено (только оптимизатор и интерпретатор): `Phi`, `Pi`, `DataAddr`, `ConstRef`, `Line`, `Note`, `each_mut`, `removable`, `Auto`.
- Текст `Debug` строки: ASCII и C1-управляющие как в Rust; остальной не-ASCII пишется как есть. Rust ещё экранирует комбинирующие символы и непечатаемые по своим таблицам. На CIR это не влияет, только на текст дампа; в корпусе не-ASCII нет.

Ловушки, которые попались здесь:
- `me.sret = vreg(&me)` запрещено (`E0158`): нужна промежуточная переменная.
- **Ошибка компилятора, не исправлена:** имя экземпляра шаблона строится из имён типов, а имя типа не содержит модуль. Два типа с одним именем из разных модулей дают один `push[P]`, и второй вызов падает с `E0104 expected &[]P, found &[]P`. Поэтому в `cir` типы называются `CirFunc` и `CirBlock`, а не `Func` и `Block`. То же в Rust и в `sema.claw`.
- `sure false` на месте `unreachable!`: остаётся проверкой и в `claw build`.


## Задний конец (`arm64`, `codegen`, `macho`, `main`, `dump_golden`)

Мерка: `claw build --no-opt f -o x` и `main f -o x` дают **одинаковые байты** (`cmp`), включая LC_UUID (первые 16 байт sha256 от кода и rodata) и подпись (ident — имя выходного файла, поэтому сравнивать надо файлы с одним именем в разных папках). То же для `--fast` и `--alloc-stats`. Корпус: `tests/{run,own,check,unit,fast,stats,why,auto,fix,info,fmt}/**`, `benchmarks/`, `benchmarks/tokens/`, программы `selfhost` с `main`: 440 файлов, в каждом режиме 392 одинаковых, 45 одинаковых ошибок (тот же stderr и код выхода), 3 исключения (вычисляемые `const`: `tests/run/const_computed`, `tests/run/const_computed_uses`, `tests/info/sig_all`). `main check` на `tests/err` совпадает с `claw check`, кроме пяти `const_computed_*` (там Rust вычисляет и находит свою ошибку, порт отвечает `E0174`). Энкодер: `dump_golden` печатает ту же таблицу, что `claw __encoder-golden` (126 строк), и `llvm-mc` с ней согласен.

Как устроено:
- `codegen` повторяет только путь `optimized == false`: каждый регистр CIR — слот `spill_base + v * 8`, сохраняемых регистров нет. `Place`, `allocate`, слияние сравнения с переходом, `indexed_access` и счёт `uses` не перенесены: без оптимизатора они не срабатывают. Мёртвых функций без оптимизатора нет, но проверка `dead` оставлена.
- `mov_imm` берёт `u64`: битовый образ, `i64` Rust не нужен. Границы `float_range_check` собраны прямо из битов (`2^k` это `(1023 + k) << 52`), без `powi`.
- `Option` везде `-1`; `m.check` читается через `else cir.CheckRt{-1, -1, -1}`.
- Варианты разных перечислений в одном модуле: `Target` стал `TgUser`, `TgTrap`, ...; `Slot` стал `SlotX/SlotD/SlotStack`. В `match` варианты пишутся без модуля (`Eq:`), при создании с модулем (`arm64.Eq`).
- `and`, `ret`, `str` — занятые слова: энкодеры `and_x`, `ret_x`, `str_x`; `B`/`BL` стали `b_op`/`bl_op`. Регистры в `codegen` объявлены своими константами (`x9 u32 = 9`), чтобы не писать `arm64.x9` сотни раз.
- Ошибки печатаются как `render_text` Rust: первые 20 и строка `N more errors not shown`. `diag.render` этого не делает (`dump_sema` сверяется без ограничения), поэтому срез в `main.report`.
- `main run`: `posix_spawn` + `waitpid` (в `rt`), код выхода или `128 + сигнал`, папка `$TMPDIR/claw-run-<pid>` удаляется после запуска. Временный файл при записи — `путь.tmp` (`rt.write_exec`), в Rust `путь.tmp<pid>`; на байты не влияет.

Ловушки, которые попались здесь:
- `const x = 9` имеет тип `int` и в `u32` не подставляется: нужен `const x u32 = 9`. Числовая константа с типом и литералом не считается вычисляемой.
- Многострочных строк нет; `const` строки с переводами тоже нельзя собрать — текст помощи стал функцией.
- `else { ... }` обязан выйти, даже если внутри `rt.exit`: типа «не возвращается» нет. Отсюда `compile_to_cir ... ! Halted` и `else { ret }` у вызывающего.
- `--no-opt --fast` в Rust оставляет проверки переполнения и границ: их снимает оптимизатор. Поэтому `tests/fast/no_bounds` и `tests/fast/wraps` в этом режиме падают с 101 и у Rust, и у порта (байты одинаковые).
