# Claw: план языка

## Context

Папка `/Users/markuza/dev/claw` пустая. Мы с нуля делаем низкоуровневый компилируемый язык **Claw** (от claw'd), целиком написанный Claude. Машина: Mac на ARM64, стоят Rust, clang, Python, Homebrew LLVM (нужен только для проверки нашего вывода).

Твои требования:
- база минимальная, ручная память + `defer`, но есть лёгкий путь для тех, кому надо быстро и без возни;
- синтаксис между минимализмом C и нашим собственным стилем: читабельный, свежий, немного примитивный;
- сразу свой ARM64-бэкенд, без LLVM;
- удобно и ИИ, и людям: 1-2 способа сделать одну вещь, минимум токенов, очень жёсткие проверки (особенно для слабых моделей, которые не умеют написать тест и найти причину);
- язык должен **выделяться**, а не быть очередной заменой C.

# ЧАСТЬ 1. Для тебя

## 1. В чём идея

Почти все новые системные языки отвечают на вопрос «как сделать C получше». Claw отвечает на другой:

> **Какой системный язык нужен, если код пишет ИИ, а отвечает за него человек?**

У ИИ другие слабые места, чем у человека. Он не устаёт печатать, зато:
- **не знает новый язык** (его не было в обучении);
- платит за каждый токен: и когда пишет, и когда читает код, и когда читает ошибки;
- **уверенно ошибается** и плохо находит причину падения;
- пишет слабые тесты, которые проверяют то, что он и так думает.

Из этого вытекают 8 вещей, которые делают Claw непохожим на других.

## 2. Восемь отличий Claw

### 1) Язык, который помещается в промпт
Жёсткое правило: **весь справочник языка (`claw card`) не больше 2000 токенов**. Любая модель, даже слабая, получает его в промпте и сразу может писать на Claw. Каждая новая фича должна «оплатить» своё место в карточке, иначе её не будет. Я не знаю другого языка с таким бюджетом на размер спецификации.

### 2) Лапа и Коготь: один язык, две передачи
Это ответ на твоё «для тру-прогеров и для тех, кому надо быстро».

- **Лапа (paw)**, обычный `fn`. Никаких указателей, `free`, GC и lifetime'ов. Память освобождается сама и предсказуемо, в конце области видимости.
- **Коготь (claw)**, `claw fn`. Голые указатели, `alloc`/`free`, `defer`, адресная арифметика, никаких страховок. Как чистый C.

Под капотом основа одна, твой первый вариант: ручная память. Лапа просто заставляет компилятор написать `defer free(...)` за тебя. **Рантайма нет, сборщика нет.** Стандартная библиотека (`[]T`, строки) написана на Когте.

Как Лапа обходится без borrow checker? Очень простым правилом: **в обычном коде ссылку нельзя сохранить или вернуть.** Значение всегда принадлежит ровно одному владельцу. В функцию оно передаётся одним из трёх способов: «почитать» (по умолчанию), «поменять» (`&`, как ссылка в C++) или «отдать насовсем» (`own`, как `std::move`). Первые два живут только на время вызова. Деревья и списки работают через владение, графы через индексы. Висячих ссылок просто негде взять, циклов нет, утечек нет. И весь этот анализ занимает сотни строк, а не годы работы, как borrow checker в Rust.

Бонус для скорости: в Лапе не бывает алиасинга, то есть **всё работает как `restrict` в C, причём бесплатно.**

### 3) Контракт сразу и документация, и проверка, и тест, и оптимизация
```claw
fn avg(xs []int) int
    need len(xs) > 0
    sure ret >= min(xs)
{
    ret sum(xs) / len(xs)
}
```
`need` это что функция требует, `sure` что гарантирует (`ret` здесь значит результат, `old(x)` значение до вызова). Простые условия компилятор **доказывает** и удаляет проверку (быстрее!) либо проверяет в рантайме. Дорогие условия с вызовами функций, как `min(xs)` выше, работают в `claw run` и `claw test`, а `claw build` прямо пишет, сколько таких условий он не проверил. Контракт не может иметь побочных эффектов и не может сам упасть от переполнения.

### 4) Тесты пишет компилятор
`claw test` без единого написанного теста берёт все функции без побочных эффектов и бьёт по ним: граничные значения (0, -1, MAX, пустой массив), потом случайные и подобранные по покрытию кода входы. Падение сокращается до минимального примера. Это встроенный фаззер, и вот зачем нам свой бэкенд: инструментировать код мы можем как угодно. Слабой модели больше не надо уметь писать хорошие тесты.

### 5) `claw why`: не где упало, а почему
Обычно ты получаешь адрес и стек, а дальше час в отладчике. Здесь компилятор перезапускает падение (оно детерминировано) и прослеживает, откуда взялось плохое значение. Показывает только строки, которые реально на него повлияли:
```
FAIL need b != 0  in div  math.claw:3
input  avg([])
why    stats.claw:12  n := len(xs)    n = 0
       stats.claw:13  ret total / n   b = n = 0
fix    add `need len(xs) > 0` to avg
```
Около 50 токенов вместо сессии в lldb на тысячи.

### 6) Подпись функции говорит правду (эффекты)
```claw
fn load(path str) Config ! IoErr +io +mem { ... }
fn hash(s str) u64 { ... }
```
`+mem` значит «выделяет память», `+io` «трогает внешний мир». Если плюсов нет, это **гарантия компилятора**: функция не лезет в сеть, не выделяет память. Человек видит, какие функции безопасны для realtime-кода и ядра, а ИИ может **не читать тело функции**: достаточно подписи. Именно это экономит токены сильнее всего, и благодаря этому возможен пункт 4.

### 7) Считаем токены всего цикла, а не длину кода
Токен не равен символу. Для LLM обычное слово `return` это один токен, а придуманное `rtrn` может быть два. Поэтому:
- ключевые слова только обычные короткие английские слова, каждое в один токен;
- нет `;`, нет лишних скобок, нет `return` дважды по-разному, один формат кода без настроек;
- ошибки компилятора компактны, у каждой есть готовый патч, `claw fix` его применяет;
- `claw sig файл` показывает только подписи, `claw ctx функция` минимальный нужный контекст.

Набор бенчмарков по токенам будет частью тестов. Цель: на 30-40% меньше токенов, чем C и Rust, на наборе из 20 задач. Это цель, замерим на итерации 8.

### 8) От исходника до бинарника только наш код
Нет LLVM, нет ассемблера, нет линкера. Компилятор сам кодирует ARM64-инструкции, сам собирает Mach-O файл, сам его подписывает (своя реализация SHA-256). Ближе к концу компилятор будет написан на самом Claw. Это и есть «made by Claude» в полном смысле.

**Честно про новизну:** по отдельности эти идеи уже где-то были (Hylo, Koka, Ada/SPARK, Zig, rr). Нового здесь их сочетание и то, что весь язык подчинён одной цели. Ни одного кирпича мы не берём просто «потому что так принято».

## 3. Синтаксис

Правило стиля: **странной пунктуации нет, свежесть в смыслах.** `fn`, `if`, `for` остаются знакомыми, потому что любая модель уже понимает их без обучения. Своё только там, где это даёт пользу: `need`, `sure`, `fail`, `+mem`, `claw fn`.

### Всё основное на одном экране
```claw
use fs                                 // импорт, один файл = один модуль

type Point { x int, y int }            // структура, в памяти как в C
type Shape = Circle{r f64} | Rect{w f64, h f64}   // вариант, как enum + union

const limit = 1000                     // глобальные значения только const

fn area(s Shape) f64 {
    match s {                          // не перечислил все случаи = ошибка
        Circle{r}: ret 3.14 * r * r
        Rect{w, h}: ret w * h
    }
}

fn main() {
    x := 5                             // тип выведен, менять нельзя
    y i32 = 7                          // тип указан явно
    mut sum := 0                       // mut = можно менять
    for i in 0..10 { sum += i }        // for единственный цикл
    for sum > 100 { sum -= 1 }         // это его while-форма
    for { break }                      // а это бесконечный
    print("sum = {sum}, x = {x}")
}
```
Для сравнения с тем, что ты знаешь:

| | C / C++ | Python | Claw |
|---|---|---|---|
| Объявить | `int x = 5;` | `x = 5` | `x := 5` или `x int = 5` |
| Изменяемое | всегда | всегда | только `mut x := 5` |
| Логика | `&& \|\| !` | `and or not` | `and or not` |
| Массив | `std::vector<int>` | `list` | `[]int` |
| Массив фикс. | `int a[4]` | нет | `[4]int` |
| «Меняю аргумент» | `int& x` | нет | `x &int`, вызов `f(&x)` |
| Строка | `std::string` | `str` | `str` |
| Шаблон | `template<class T>` | нет | `fn max[T](a T, b T) T` |

`int` всегда 64 бита, `len()` возвращает знаковый `int`: это убирает целый класс ошибок с `size_t - 1`. Побитовые операторы как в C: `& | ^ ~ << >>`. **Знаковые числа при переполнении падают, беззнаковые (`u8`, `u64`) заворачиваются**, как в C: для хешей и криптографии это и нужно.

**Перенос строк:** конец строки завершает инструкцию, кроме случаев, когда строка заканчивается оператором, запятой или открытой скобкой. Одна инструкция на строку, поэтому `;` не нужна.

### Ошибки: одна механика
```claw
type ParseErr = Empty | BadChar{at int}

fn parse(s str) int ! ParseErr {       // ! = может вернуть ошибку
    if len(s) == 0 { fail Empty }      // fail = вернуть ошибку
    mut n := 0
    for c, i in s {
        if c < '0' or c > '9' { fail BadChar{i} }
        n = n * 10 + int(c - '0')
    }
    ret n
}

fn main() {
    a := parse("42")?                  // ? = передать ошибку выше
    b := parse("x") else 0             // else = обработать на месте
    c := parse("y") else e {           // блок обязан выйти: ret, fail, break
        print("{e}")
        ret
    }
}
```
`else` бывает двух видов: значение по умолчанию или блок, который выходит из функции. `?` в `main` печатает ошибку и завершает программу с кодом 1. Проигнорировать ошибку нельзя, это ошибка компиляции. Исключений нет. Отсутствие значения пишется `?T` (и `none`), обрабатывается теми же `?` и `else`. `null` в Лапе не существует.

### Методов нет, всё обычные функции
```claw
mut a []int = []
push(&a, 3)            // & на вызове: сразу видно, что a изменится
print(len(a))
sort(&a)
```
Нет классов, наследования, перегрузки операторов, исключений, макросов, замыканий. Функцию можно передать как значение (`fn(int) int`), но только именованную. Нужная функция находится по типу первого аргумента (как ADL в C++), поэтому `push`, а не `vec.push`. Добавлять такие функции может только модуль, где объявлен тип. Примитивно и на этом держится вся простота.

### Лапа: память сама
```claw
fn names() []str +mem {
    mut a []str = []
    push(&a, "cat")
    ret a               // отдаём, копии нет
}

fn main() {
    a := names()
    b := a              // это последнее использование a: a переезжает в b
    c := copy(b)        // копию надо просить явно
    print(len(b) + len(c))
}                       // тут компилятор сам освободит b и c
```
Если написать `b := a`, а потом использовать `a`, будет ошибка компиляции с готовым патчем «напиши `copy(a)`». Дорогие копии никогда не бывают скрытыми.

Три способа передать значение в функцию:
```claw
fn total(a []int) int           // почитать (по умолчанию)
fn clear(a &[]int)              // поменять, вызов clear(&a)
fn keep(own s str) Box +mem     // забрать себе, вызов keep(s)
```
Два простых правила защищают от ошибок:
- **Переехать может только целая локальная переменная.** Взять значение из середины нельзя: для `b := a[0]` нужен `copy(a[0])` или `remove(&a, 0)`.
- **Пока идёшь по массиву, его нельзя менять.** `for x in a { push(&a, x) }` это ошибка компиляции, а не падение в рантайме.

Свой тип может описать освобождение функцией `drop(x &T)`: компилятор вызовет её сам (закрыть файл, отпустить ресурс).

### Коготь: полный контроль
```claw
claw fn fill(p *u8, n int, v u8) {
    for i in 0..n { p[i] = v }         // без проверок, как в C
}

claw fn demo() {
    p := alloc[u8](1024)
    defer free(p)
    fill(p, 1024, 0)
}

extern fn puts(s *u8) i32              // прямой вызов C-функций
```
`claw audit` показывает все такие места в проекте: сразу понятно, где искать опасный код. В режиме проверки даже Коготь ловит выход за границы и use-after-free (своя версия ASan).

### Полный список ключевых слов (всего 28)
`fn type use pub const mut own if else for in break continue match ret fail need sure test claw defer extern and or not true false none`

Для сравнения: в C11 их 44, в Rust около 40. `print`, `len`, `copy`, `alloc`, `free`, `int` это не ключевые слова, а встроенные имена. `_` отбрасывает значение: `_ = f()`. Тесты пишутся так: `test "имя" { ... }`.

### Строгость, которую нельзя выключить
Нет неявных преобразований типов. Неиспользованная переменная или результат функции это ошибка. Запрещено перекрывать имена. Все переменные инициализированы. `match` полный. Знаковое переполнение и выход за границу массива ловятся. Форматирование одно на всех, и применяется автоматически. Свои типы и варианты всегда с большой буквы, всё остальное с маленькой.

## 4. Режимы и команды

| Команда | Что делает |
|---|---|
| `claw run f.claw` | режим проверки: всё проверяется, запускает сразу |
| `claw build f.claw` | быстрый бинарник: оптимизации, остаются только недоказанные проверки |
| `claw build --fast` | все проверки сняты, скорость как у C, ответственность твоя |
| `claw test` | твои `test`-блоки + авто-тесты по контрактам |
| `claw why` | причина последнего падения |
| `claw fix` | применить патчи из ошибок |
| `claw sig` / `ctx` / `card` / `audit` | подписи / контекст / справочник / опасные места |

## 5. Скорость: прогноз

**Это прогноз, а не замеры:** компилятора ещё нет. Числа основаны на том, что обычно дают наивные и простые оптимизирующие компиляторы. Настоящие замеры будут в `benchmarks/RESULTS.md` на итерации 1 и при каждом следующем релизе. C-версии тех же бенчмарков лежат рядом.

Время относительно `clang -O2` (1.0 = столько же, больше = медленнее):

| Задача | `clang -O0` | Claw без оптимизаций (v0.1-0.5) | Claw с оптимизациями, проверки вкл. (v0.6) | Claw `--fast` (v0.6) |
|---|---|---|---|---|
| `fib(40)`, вызовы функций | ~2x | ~3x | ~1.3x | ~1.2x |
| Решето 100 млн, память | ~2x | ~3x | ~1.2x | ~1.1x |
| N-body, дробные числа | ~3x | ~4x | ~1.5x | ~1.4x |
| Матрицы 1000×1000 | ~10x | ~15x | ~3-4x | ~3x |
| Хеш-таблица, 10 млн вставок | ~2x | ~2.5x | ~1.2x | ~1.1x |

Для ориентира: `fib(40)` на M-серии примерно 0.3-0.4 с у `clang -O2`, значит ждём около 1 с без оптимизаций и 0.4-0.5 с с ними.

Матрицы проигрывают сильнее всего: LLVM автоматически векторизует циклы, а мы на первых порах нет. Закроем ручными SIMD-типами в Когте (итерация 10). Обогнать `-O2` в среднем мы не обещаем, на это у LLVM ушли десятилетия. Наши козыри: отсутствие алиасинга и контракты, которые убирают проверки.

**Скорость компиляции** это то, где мы должны выигрывать: цель 300 000+ строк/с без оптимизаций, то есть проект на 20 000 строк примерно за 50-70 мс, с оптимизациями в 3-5 раз дольше. Для ИИ это важно: цикл «написал, проверил, поправил» почти мгновенный.

## 6. Роадмап: 10 итераций

Каждая итерация заканчивается рабочей версией `claw-0.N` в PATH, прогоном всех тестов (включая тесты прошлых итераций) и отчётом, что из синтаксиса готово.

| # | Название | Что появляется | Результат, который можно потрогать |
|---|---|---|---|
| 1 | **Первая царапина** | `fn`, `int`, `bool`, `:=`, `mut`, `if`, `for`, `ret`, `print`, ловля переполнения. Свой ARM64, Mach-O, подпись | `claw run fib.claw` работает без clang и ld |
| 2 | **Скелет** | все числа, `f64`, структуры, `[N]T`, варианты, `match`, `?T`, `T ! E`, строковые литералы и `{x}` внутри `print`, строгие проверки, форматтер, формат ошибок, учёт размера карточки | настоящие небольшие программы без кучи |
| 3 | **Коготь** | `claw fn`, указатели, `alloc/free`, `defer`, `extern`, шаблоны, модули, вызовы C | можно писать на уровне C |
| 4 | **Лапа** | `[]T`, `str`, владение, `own`, `&`, авто-освобождение, `drop`, std на Claw | обычный код без ручной памяти |
| 5 | **Честные подписи** | `need/sure`, эффекты `+mem/+io`, `test`, режим проверки с ASan для Когтя | контракты и гарантии работают |
| 6 | **Скорость** | SSA, инлайнинг, распределение регистров, удаление доказанных проверок | большой скачок производительности, таблица замеров |
| 7 | **След когтя** | интерпретатор IR, авто-тесты, фаззер, `claw why`, `claw fix`, вычисления при компиляции | компилятор сам находит баги и причины |
| 8 | **Экономия** | `claw card/sig/ctx/audit`, бенчмарк токенов, экзамен для слабой модели (Haiku пишет на Claw только по карточке), std | доказательство главной идеи в цифрах |
| 9 | **Сам себя** | компилятор переписан на Claw, собирает сам себя | Claw написан на Claw |
| 10 | **Наружу** | отладка в lldb (DWARF), ARM64 Linux, x86-64, SIMD, параллельность без гонок, LSP для редактора | готов для других людей |

Порядок можно менять. Итерация 8 может идти раньше, если захочется быстрее проверить главную идею.

## 7. Что я решил за тебя (скажи, если не нравится)

1. **Лапа по умолчанию**, Коготь надо попросить словом `claw`. Основа всё равно твоя ручная: Лапа просто её автоматизирует. Опасное видно и ищется поиском, а слабая модель не сможет случайно написать небезопасный код.
2. **Первый компилятор на Rust без единой внешней зависимости.** Rust похож на C++ без классов, и его строгие `match` ловят мои ошибки в самом компиляторе. На итерации 9 он заменится компилятором на Claw.
3. **Только macOS ARM64 до итерации 10.** Сфокусированно и без распыления.

# ЧАСТЬ 2. Техническая

## Стек
- Stage 0: Rust stable, ноль crates, один бинарник `claw`.
- Инструменты тестов: Python 3 (`tools/`).
- Только для проверки, не для сборки: `otool`, `codesign -v`, `/opt/homebrew/opt/llvm/bin/llvm-objdump`, `lldb`, `clang` (C-бенчмарки).

## Структура репозитория
```
CLAUDE.md
compiler/src/{main,lexer,parser,ast,sema,own,cir,interp,opt,regalloc,arm64,macho,sha256,diag,fmt}.rs
std/                          # библиотека на Claw
tests/{run,err,fix}/          # run: // expect: вывод; err: // error: E####
benchmarks/{*.claw,*.c,run.py,RESULTS.md}
docs/{SPEC,CARD,STATUS,DECISIONS}.md
tools/{runtests,install}.py
```

## Конвейер
`lexer → parser → AST → sema (типы, имена, эффекты) → own (перемещения, эксклюзивность, вставка drop) → CIR → opt → regalloc → arm64 → macho + подпись`

- **Парсер:** ручной рекурсивный спуск + Pratt для выражений. Неоднозначность `x [4]i32 =` против `x[4] =` снимается токеном после `]`. Содержимое `[...]` разбирается единой грамматикой тип-или-выражение (`alloc[[]int](n)`), смысл определяет sema.
- **Перевод строки:** лексер вставляет терминатор, кроме строк, оканчивающихся на бинарный оператор, запятую или открывающую скобку; внутри `()` и `[]` переводы игнорируются. После сигнатуры парсер пропускает переводы перед `need`, `sure`, `{`.
- **Заголовки `if/for/match`:** struct-литерал и `else` только в скобках (правило Rust), иначе `if e == Empty {` неоднозначно. Блок `else` обязан завершаться выходом.
- **Ошибки:** единая структура `{code, span, msg, fix?: [(span, text)]}`. По умолчанию одна компактная строка на ошибку, `--json` для инструментов. Лимит 20 ошибок, без каскадов.
- **Шаблоны:** мономорфизация, ошибки показываются в месте вызова.

## CIR (наш IR)
Типизированные инструкции над виртуальными регистрами, блоки, явные `trap(id)`. Один IR от итерации 1 до конца, меняется только то, что вокруг него.
- v0.1-0.5: каждый vreg это слот на стеке. Загрузил, посчитал, сохранил.
- v0.6: SSA (алгоритм Braun et al.), const fold, copy prop, DCE, инлайнинг, GVN, LICM, range analysis с удалением проверок и доказательством `need/sure`, linear scan по live intervals.
- Интерпретатор CIR (v0.7) один закрывает три задачи: вычисления при компиляции, детерминированный replay, теневое отслеживание зависимостей для `claw why`.

## ARM64 и Mach-O
- Энкодер: по функции на инструкцию, golden-тесты против `llvm-objdump`.
- ABI: AAPCS64 с поправками Apple (вариативные аргументы на стеке, стек выровнен на 16). `x18` не трогаем.
- Mach-O пишем сами: `__PAGEZERO`, `__TEXT` (страницы 16K), `__DATA_CONST` с GOT, `__DATA`, `__LINKEDIT`; `LC_MAIN`, `LC_LOAD_DYLINKER`, `LC_LOAD_DYLIB` libSystem, `LC_DYLD_CHAINED_FIXUPS`, `LC_DYLD_EXPORTS_TRIE`, `LC_SYMTAB`, `LC_DYSYMTAB`, `LC_BUILD_VERSION`, `LC_CODE_SIGNATURE`.
- ARM64 macOS не запускает неподписанные бинарники, поэтому пишем ad-hoc подпись: SuperBlob + CodeDirectory, SHA-256 на страницу 4K, флаг adhoc.
- Детали подписи и формата сверяем со свежим выводом `clang`, а не по памяти: `LC_UUID`, флаги `NOUNDEFS|DYLDLINK|TWOLEVEL|PIE`, CodeDirectory v20400 c флагами `0x20002` и exec-segment полями, `codeLimit` = смещение подписи, `__LINKEDIT` покрывает подпись, подпись считается последней, fixup starts на каждый сегмент включая `__PAGEZERO`, пустой `__DATA` не пишем.
- Бинарник всегда пишем во временный файл и делаем `rename`: перезапись запускавшегося файла на месте ломается из-за кэша подписи в ядре.
- Статической линковки на macOS нет, syscall ABI нестабильно: импортируем `write/malloc/free/exit` из libSystem.
- **Запасной вариант:** если загрузчик на Darwin 27 не примет наш файл быстро, временно выводим `.s` через системные `as+ld`, чтобы итерация не встала, сообщаем об этом и возвращаемся к своему писателю в той же итерации.

## Семантика Лапы (`own`)
- Значения с кучей: `[]T`, `str`, варианты с ними, рекурсивные `?T` (неявный бокс; создание значения считается `+mem`). `??T` запрещён.
- Владеющая раскладка `{ptr,len,cap}`; `cap == 0` значит статические данные, `free` не вызывается. Поэтому `push(&a, "cat")` безопасен.
- Параметры: read-вью (`[]T`/`str` как `(ptr,len)`), `&T` (указатель), `own T` (перемещение). Вью и `&` живут только на время вызова, сохранить или вернуть нельзя.
- Move только из целых локальных переменных и `own`-параметров, на последнем использовании (liveness), иначе E-ошибка с патчем `copy(x)`. Из полей и элементов только `copy`, `remove`, `swap` или деструктуризация владеющей локальной. Условные перемещения решаются drop-флагами.
- Эксклюзивность: пути сравниваются по всему вызову включая вложенные; `f(a[0], g(&a))` и `f(&a[i], a[j])` запрещены (два индексных пути на одном корне, если один из них `&`).
- Переменные `for` и привязки `match` держат read-lock на корне на всё тело. Опустошение через `pop(&a)`.
- `drop(x &T)` ищется обычным поиском по первому аргументу. Типы с `*T` внутри создаются только в `claw fn`; Лапа вызывает лишь `claw fn` без указателей в подписи.
- Глубокий drop: цепочка через единственное рекурсивное поле превращается в цикл, чтобы длинный список не переполнил стек; остальное рекурсивно.
- `&a[i..j]` (мутация подмассива) в v0.4 не поддерживается; решение записать в DECISIONS.

## Проверка и эффекты
- `need/sure/+effects` парсятся и хранятся в AST начиная с v0.2, проверяются с v0.5: иначе std из v0.4 пришлось бы переделывать.
- Эффекты: `+mem +io` (время и случайность входят в `+io`). У `pub` функций объявлены явно и являются верхней границей, проверяемой для каждой инстанциации шаблона. У приватных выводятся по SCC графа вызовов после проверки типов (с патчем от компилятора). `main` имеет все.
- Контракты: без эффектов; на время вычисления контракта проверки контрактов выключены (нет бесконечной рекурсии в `sure ret == sum(xs)`); целые внутри контракта расширенные, без переполнения; `old(e)` для состояния до вызова `&`-параметров. Контракты с вызовами функций работают только в `run/test`, `build` сообщает их число.
- Переполнение: знаковые `trap`, беззнаковые заворачиваются. Фаззер сообщает переполнение отдельным классом «не хватает `need`».
- `claw fn` обязан декларировать те же эффекты, но компилятор верит ему на слово: поэтому `claw audit` их показывает.
- Режим проверки: `adds + b.vs → trap`, bounds, контракты, shadow-память и карантин для `alloc/free`.
- Вся недетерминированность идёт через слой runtime и записывается при `claw run`, это база replay. Запись `extern`-вызовов и виртуализация адресов `malloc` закладываются в codegen с v0.3; произвольный `extern` помечается «не воспроизводимо».
- `{x}` в v0.2 работает только внутри `print`, через стековый буфер, без кучи. Форматирование `f64` временно идёт через `snprintf` из libSystem.
- Карточка: ядро языка до 2000 токенов (`docs/CARD.md`, проверка размера в тестах с v0.2, приближённым счётчиком), описание std не входит и выводится `claw sig std`.

## Авто-тесты и `why`
- Кандидаты: функции без `+io`, с типами параметров, для которых можно сгенерировать значения. `need` фильтрует входы.
- Генератор: граничные → случайные → мутации по покрытию (счётчики рёбер в CIR). Seed фиксирован, усадка входа.
- `why`: replay минимального входа в интерпретаторе CIR, у каждого значения последний def-event, обратный проход от failing check, вывод только затронутых строк.

## Версионирование и конец итерации (идёт в CLAUDE.md)
`tools/install.py` кладёт сборку в `~/.claw/versions/0.N/{claw,std}`, создаёт `~/.claw/bin/claw-0.N` и обновляет симлинк `~/.claw/bin/claw`. **Старые версии не удаляются никогда.**

Чек-лист в конце каждой итерации:
1. `cargo build --release`, без предупреждений.
2. `tools/runtests.py`: все тесты всех итераций.

4. Обновить `docs/STATUS.md` (фича → готово / частично / нет) и `benchmarks/RESULTS.md`.
5. git commit + тег `v0.N`.
6. Отчёт пользователю простым языком: что из синтаксиса работает, что нет.
