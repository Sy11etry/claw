# Статус языка: claw 0.9

Что реально работает в установленной версии. Обновляется в конце каждой итерации.

## Частично

| Возможность | Что есть | Чего нет |
|---|---|---|
| Доказательство контрактов | снимается то, что следует из диапазонов чисел и сравнений на пути к проверке | рассуждений о содержимом массивов, инвариантов циклов сложнее простых счётчиков |
| Векторизация | нет | SIMD вручную, итерация 10 |
| Контракты с вызовами | работают в `claw run` и `claw test`; `claw build` пишет, сколько их пропущено | проверки в `claw build` |
| Эффекты в `claw fn` | видимые `alloc`, `print` и вызовы проверяются | `extern` принимается на веру; список мест появится с `claw audit` |
| Проверка памяти | куча | стек и статические данные; что делает функция по `extern` |
| Форматирование | команда `claw fmt` | автоматического запуска при сборке |
| Строки `{x}` как значение | работают | длиннее 64 КБ завершаются ошибкой; кавычки внутри `{...}` писать нельзя |
| Рекурсивные типы | через `[]T`: `type Tree { kids []Tree }`, и через указатели в `claw fn` | неявный бокс для `?T`, обещанный в плане |
| Перемещение | только целые локальные переменные | разбора значения на части без копирования (кроме `remove`, `swap`) |
| Печать дробных | до 15 значащих цифр для `f64`, 7 для `f32`, через `snprintf` | точного кратчайшего представления; `3.0` печатается как `3` |
| `claw fix` | применяет патчи: добавить или убрать `mut`, добавить `&`, `copy(x)`, эффекты | `_ = f()`, переименование в `_` и `claw fn` намеренно остаются подсказками |
| Автотесты | функции корневого файла с параметрами-значениями | шаблонов, функций с указателями в параметрах, функций с `+io`, импортированных модулей |
| Переполнение в автотестах | заметка с примером входа, код выхода 0 | провала при переполнении |
| `claw why` | исполняет программу заново в интерпретаторе, ввод-вывод повторяется | воспроизведения именно того запуска, что упал; функций C вне встроенного списка (`snprintf` и другие) |
| Патч в `why` | деление, границы, сдвиг, преобразование, `alloc`, `need` вызываемой функции | если значение зависит от `mut` или счётчика цикла; для переполнения |
| Вычисления при компиляции | любые функции без `+io`, все контракты включены | размера массива; значений с кучей и указателями, кроме `str` |
| Отладка | lldb видит имена функций | номера строк (DWARF, итерация 10) |
| Шаблоны | функции, структуры, варианты; тело проверяется для каждого использованного набора типов | неиспользованный шаблон не проверяется вообще; шаблон нельзя передать как значение |
| Функция как значение | именованные функции | замыканий; функций с `need`, `extern` и шаблонов как значений; вызова из C (колбэки); `print` показывает `<fn>` внутри структуры |
| Печать | любые значения | рекурсивного типа целиком (`E0179`): нужна своя функция обхода |
| Хеш-таблица | ключи: числа, `bool`, `str` | ключей-структур: шаблон сравнивает ключи через `==` |
| Вид на элемент | только неизменяемый `x := ...` от локальной переменной | `mut x := a[i]` требует `copy`, вид нельзя вернуть |
| Вызовы C | регистры, вариативные аргументы, узкие результаты проверены тестами | невариативные аргументы сверх восьми на стеке написаны по правилам Apple, но подходящей функции в libSystem для теста нет |

## Известные ограничения 0.9

- В `claw build` обращение по нулевому или висячему указателю падает как в C (код 139) или портит память. `claw run` ловит это для кучи и нулевого адреса.
- `/`, `%` и сдвиги в контрактах считаются как обычно и могут упасть. Умножение значений шире 64 бит в контракте завершается сообщением, а не даёт неверный ответ.
- Пока идёт контракт с вызовами, контракты с вызовами внутри него отключены, иначе `sure ret == sum(a)` не закончился бы.
- `old(x)` запоминает только числа и `bool`; для массива пишите `old(len(a))`.
- Подключается только libSystem; своих `.o` и других библиотек пока нет.
- Глубокая рекурсия заканчивается обычным падением по стеку (код 139), без понятного сообщения.
- Функция: не больше примерно 1 МБ машинного кода и 7 МБ локальных данных, иначе `E0901`. Большие данные надо класть в `[]T`.
- `claw build` компилирует в файл только то, что вызывается; но типы и тела всё равно проверяются полностью.
- Литерал `[x...]` заполняется простым циклом.
- Ошибка внутри `{...}` в строке указывает на начало всей строки.
- `claw run` и `claw test` не оптимизируют: в них важнее проверки и быстрая сборка.
- Интерпретатор в 30-40 раз медленнее `claw build` (замер на `sieve` и `mandel`). `claw why` и `__interp` останавливаются на 3 млрд шагов, это около 6 секунд: программа, которая нативно работает дольше примерно 0.2 с, может не дойти до конца (`primes` не доходит). Цикл истории хранит последние 8 млн событий; более ранние причины помечаются в отчёте.
- `claw test` бюджетирует шаги: 4000 входов и 20 млн шагов на функцию, 300 млн на файл. Функции сверх бюджета считаются пропущенными.
- `clawc` (компилятор на Claw) не оптимизирует, не вычисляет `const` с вызовом (`E0174`), не умеет `test`, `why`, `fix`, `fmt`, `sig`, `ctx`, `audit`: это по-прежнему делает `claw` на Rust.
- Шаблон, использованный с двумя типами одного имени из разных модулей (`a.P` и `b.P`), получает один экземпляр: второй вызов даёт ложную `E0104`.
- Шаблонные типы, содержащие друг друга по значению, если они создаются после раскладки, не получают `E0127`, а `sizeof` для них даёт 0.
- Цифры по токенам в `benchmarks/TOKENS.md` это оценка двумя правилами подсчёта, настоящего токенизатора здесь нет.
- Вход, из-за которого функция зациклилась или ушла в слишком глубокую рекурсию, отбрасывается, а не считается ошибкой.
