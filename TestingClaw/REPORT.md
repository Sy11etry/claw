# Отчёт Haiku: проверка Claw 0.11

Модель: Haiku 5.5. Компилятор: `claw` 0.11.0 (`~/.claw/bin`). Дата: 2026-11-13. Задания: `docs/HAIKU_TASKS.md`.
Правило «только находить и записывать» соблюдено: `compiler/` и `selfhost/` не менялись. Всё, что нашёл, записано в `TestingClaw/FINDINGS.md` (45 записей, F1–F45). Всего написано около 290 файлов `.claw`.

## Что сломано (по убыванию серьёзности)

Сломан код, то есть программа тихо получает неверный результат:

1. **Замок пакетов не проверяется в `claw run` и `claw build` (F20).** Изменённый файл `.claw/pkg/...` запускается без предупреждения: печатается `149` вместо `98`. Проверка есть только в `claw get`, а `docs/STATUS.md` утверждает обратное.
2. **Смена версии в `claw.pkg` не замечается (F21).** Указано `#v2.0`, `claw get` пишет «up to date», запускается `v1.0`.
3. **`__attribute__((packed))` игнорируется (F8).** `sizeof` структуры в claw 8, в C 5. Тихий разрыв раскладки для C-библиотек.
4. **Шаблон и структура принимают лишние аргументы типа (F31).** `Box[int, int]{1}` для `Box[T]` компилируется и печатает `1`. Для функции `pair[int, int](1)` E0144 срабатывает.
5. **Глубина рекурсии зависит от режима (F41).** `claw run` и `claw build --no-opt` падают на глубине 100 000 (код 139 и -11), `claw build` и `--fast` проходят.
6. **`sizeof` внутри макроса для размера массива даёт `[0]` (F9).** Так не собирается `curl/curl.h` из SDK. Ошибка E0126 указывает на строку перевода, а не на заголовок.
7. **Имена функций с заглавной буквы переводятся с маленькой (F10).** `BZ2_bzBuffToBuffCompress` становится `bZ2_…`, `XML_ParserCreate` становится `xML_…`. Вызов по C-имени даёт «unknown function», без подсказки нового имени.
8. **`static inline` функции молча пропускаются (F12).** `cdecl` не пишет о них, компилятор говорит «unknown function».
9. **Макросы-функции (`toupper`, `isdigit`) не переводятся (F11).** Причина не названа, обход есть: `c__toupper` или ручной `extern fn`.
10. **Незакрытый `#ifndef` принимается молча (F13).**
11. **`claw test` объявляет провал для зацикливания (F40).** В документации записано, что такой вход «отбрасывается, а не считается ошибкой».

Не сломано, но неудобно:

12. `--fast` молча возвращает неверные значения при переполнении и выходе за границу (F36). Это задумано, но пользователь об этом не знает.
13. `claw run` и `claw build` зависают на бесконечном цикле без предупреждения (F43). Лимита времени у программ нет.
14. Бесконечная рекурсия падает без сообщения (F42). Записано в STATUS как ограничение.
15. `claw run` оставляет программу жить после SIGKILL (F44): осиротевший бинарник грузил ядро пять часов.
16. E0901 для функции с большим литералом: место `1:1` неверно, совета нет (F45).
17. `u8(300)` молча даёт `44`, а `i8(300)` падает (F39). Документация не говорит, что явный перевод в беззнаковый тип обрезает.
18. `f32` печатается `1.677722e+07` для `16777216.0`, `f64` печатает `16777216` (F38).
19. `claw fix` не применяет подсказки E0105 и E0111 (F29, F30).
20. Для `claw.pkg` и `claw get`: пустая папка принимается (F23), вложенный `claw.pkg` игнорируется без подсказки (F24), пробелы и кавычки не работают (F25), в скрипте `os.args()[0]` — временный путь (F26), git шумит (F27).

## Самые запутанные сообщения компилятора

1. `E0110 function limit is defined twice` для имени константы (должно быть E0102, F28).
2. `E0152 only a whole variable can be moved` для поля параметра `p.b`: не названо выражение, `claw fix` без патча (F2).
3. `E0152 … copy it here or where it is declared`: неясно, какое место имеется в виду (F1).
4. `E0144 cannot work out R; write build[...](...)`: вторая ошибка-каскад, подсказка не объясняет, что писать (F18).
5. `E0178 add +io to the type` для задачи `par`: совет не работает, задачам нельзя `+io` (F19).
6. `E0101 unknown function toupper`: причина в макросе, компилятор не говорит (F11).
7. `E0101 unknown function BZ2_bzBuffToBuffCompress`: переименование без подсказки (F10).
8. `E0126 array size must be at least 1` в `sizes_sizeof.h:2:17`: строка перевода, а не заголовок (F9).
9. `E0146 cannot find module tools`: нет подсказки про `claw.pkg` (F22).
10. `E0150 Claw has no methods; write len(a, ...)`: неверный совет, нужно `len(a)` (F33).

Кроме этих: E0127 советует «use a pointer», что нельзя выполнить вне `claw fn` (F32); E0111 советует `_ = f()`, что для `T ! E` ведёт к E0125 (F29); E0118, E0121, E0131, E0134 короткие и без имён (F35).

## Что работает хорошо

- Экзамен: `claw why` сразу назвал строки, `claw test` сам нашёл `ratio(0, 0)` и предложил `need`. Сообщения E0147 и E0148 понятные.
- Коды E0139, E0174, E0167, E0166, E0176, E0177, E0901 понятные, с причиной или местом.
- `claw fix` применяет E0103, E0116, E0151, E0160 (после этого программа компилируется).
- Потоки: 1700 запусков бинарников (850 на arm64 и 850 на x86-64), без расхождений. Деление на ноль в задаче даёт 101 и место. Утечка внутри задачи обнаруживается.
- Сишные библиотеки: libc, zlib, sqlite3 (с колбэком на 1000 строк), libxml2, iconv, bzip2 и expat (через переведённые имена), curl (через ручные `extern`). Собственная библиотека с разными типами данных и макросами совпадает с C на двух архитектурах.
- Пакеты: папки, git-теги, `claw get --update` восстанавливает копию, понятное сообщение про `My-Lib`.
- Скрипты: аргументы с пробелами и пустой аргумент, `os.exit(3)`, `stdin` через `fs.read("/dev/stdin")`, пакет рядом со скриптом работает из другой папки.
- Режимы сборки: все 36 программ экзамена и 30 крайних значений дают одинаковый результат в `run`, `build`, `--no-opt` и `x86-64`, кроме `--fast` на программах с проверками (ожидаемо).

## Что не проверено и почему

- E0902 (форматтер отказался менять файл): четыре входа не вызвали отказ.
- E0907: в SPEC помечен «не используется».
- E0900: код зарезервирован. Одиннадцать вариантов строк с `{}` его не дали (F34).
- Замер `par.build` против цикла: только на всех 10 логических ядрах (4 быстрых и 6 экономичных). Ускорение 2,5× (задача 10 итераций), 3,8× (задача 1000 итераций), 4,2× (задача 1 000 000 итераций), результаты совпадают. На 2 и 4 ядрах не измерено: в `par` нет способа ограничить число потоков.
- Linux x86-64, Windows, WebAssembly, запуск glibc-сборки, настоящий Intel: не проверялось и требует работы человека (пункт H).

## Что нужно решить человеку

Решения по находкам:
- F20 и F21: проверять замок в `run` и `build`; при смене версии в `claw.pkg` требовать `claw get --update` с понятным сообщением.
- F8: решить, поддерживать ли `packed`, или выдавать ошибку при его встрече.
- F31: добавить проверку числа аргументов для структур.
- F10 и F11: переведённые имена и макросы-функции объяснять в сообщении и в `cdecl`.
